## Subsequent decision/evidence addendum — 2026-10-26

The database's Block Writes ON setting was not reverified following this action.

## Subsequent decision/evidence addendum — 2026-11-06 (Issue #82 / Issue #84)

- **ERD-017 — PO APPROVED ARCHITECTURAL DIRECTION — NOT IMPLEMENTED / NOT LIVE (2026-11-06):** Following Launch Readiness audit ([#82](https://github.com/fatihemres/efso-radar/issues/82)) and architecture option review ([#45](https://github.com/fatihemres/efso-radar/issues/45)), the Product Owner explicitly selected **Option B (provider-persistent cross-runner ownership journal)** for target unattended GitHub Actions + Turso automation, complemented case-by-case by **Option C (single-transaction atomic batching)** where appropriate ([PO Decision Comment 6679425019](https://github.com/fatihemres/efso-radar/issues/82#issuecomment-6679425019)). Option A (persistent-host manifest) remains recognized for supervised, single-machine controlled staging sessions only, not unattended cloud recovery.
  - **Hard Boundaries Preserved:** This decision selects architecture direction only. It does **NOT** authorize Schema v7 or any migration, table creation, journal implementation, live staging reads or writes, token generation, Block Writes modification, Gemini/RSS/Telegram, cron schedules, backup, or budget changes.
  - **Safety Invariant:** Ambiguous journal intent COMMIT ⇒ UNKNOWN / HALT (never dispatch effects or blind retry); ambiguous effect COMMIT ⇒ UNKNOWN / manual read-only reconciliation after separate PO approval; foreign or stale ownership fencing ⇒ HALT without automated cleanup.
  - **Reuse Contract:** Reuses existing Schema v6 controls for task concurrency (`run_locks`), execution history (`scheduled_execution_history`), Telegram deduplication (`telegram_delivery_records`), and AI budget limits (`ai_usage_ledger`). Staging synthetic target lifecycle (`durable_recovery_state`) and ordinary production operations must not share one table or namespace. All cloud operations strictly **$0.00 / 0 TRY**.
  - **Issue #92 Offline Seam Integration (2026-11-07):** Bounded offline integration (`StagingJournalHranaSeam`) validated atomic Option B+C transactions over mock Hrana transport. Real remote Hrana interactive transaction guarantees and cross-runner durability across ephemeral CI runner VM destruction remain UNPROVEN / BLOCKED.

- **ERD-018 — ENGINEERING PROPOSAL / UNDER INDEPENDENT REVIEW — NOT PO ACCEPTED (2026-11-06; Issue #88):** Following Launch Readiness audit ([#82](https://github.com/fatihemres/efso-radar/issues/82) G1/G3/G6) and Gemini Free Tier Safety ([#86](https://github.com/fatihemres/efso-radar/issues/86)), the Product Owner authorized bounded offline preparation only ("tamam devam edelim" / [#88](https://github.com/fatihemres/efso-radar/issues/88)). The resulting G3 Gemini activation safety contract and integration plan is an **engineering proposal under independent review**, NOT a PO-accepted architecture or activation authorization.
  - **Contract & Architecture Proposal:** Evaluates `gemini-3.5-flash-lite` as the sole evaluated launch model, search grounding disabled (unavailable on Free Tier), static owner-observed project quota snapshots on 2026-11-06 (15 RPM, 250k input TPM, 500 RPD with US Pacific midnight reset, and 300 monthly calls cap), pre-dispatch candidate decision state machine (`evaluate_g3_activation_preflight`), strict fail-closed machine gates, and unconditional client-side blocking barrier (`require_verified_free_tier()`).
  - **No False Authority (`allowed=False`):** `evaluate_g3_activation_preflight()` NEVER returns `allowed=True` or `ALLOW_PREFLIGHT_READY`. When all structural checks pass in synthetic simulation, it returns `allowed=False, status_code="SIMULATION_PASS_NON_AUTHORIZING"`.
  - **Five Mandatory Activation Blockers:** Live authorization is permanently blocked by missing infrastructure: (1) G1 provider billing attestation (Google Cloud Billing API); (2) G2 / ERD-017 provider-persistent cross-runner quota reservation and ownership journal; (3) trusted provider quota freshness and observation timestamp; (4) project/model binding attestation; (5) authenticated session-scoped human PO Live GO grant validation. The caller boolean `is_po_live_go_granted` is a simulation parameter, not an implemented authorization system.
  - **Schema Reuse & Gap Matrix:** Reuses Schema v6 `run_locks` (single-runner serialization) and `ai_usage_ledger` (audit and ambiguous failure recording). Unattended multi-runner rolling-window quota reservation is formally mapped as a dependency on G2 / ERD-017, avoiding premature Schema v7 migration.
  - **Hard Boundaries Preserved:** Strictly **$0.00 / 0 TRY** operating policy; zero live Gemini API calls, zero Turso connections (including reads), zero credentials, and no live activation.
