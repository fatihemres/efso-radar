## 2026-10-31 Context7 CLI security evaluation

Antigravity independently inspected local `ctx7@0.8.2` and reported that stock `ctx7 setup --cli --antigravity` would add an auto-trigger rule to global `~/.gemini/GEMINI.md` and initiate OAuth. This setup was not run. The PO subsequently authorized a **bounded anonymous public-doc CLI test**, executed on Windows per Antigravity: `CTX7_TELEMETRY_DISABLED=1` with `npx ctx7@0.8.2 library pydantic "model validation in Pydantic v2"` followed by `npx ctx7@0.8.2 docs /pydantic/pydantic "how model_validate works in Pydantic v2"`. Both public requests returned relevant upstream docs; no login, credential file, skill, MCP, global rule or repo changes were reported. These were external Context7 service requests — **not hermetic**; set environment variables per invocation and do not infer end-to-end telemetry suppression from client settings alone. The local agent report is not independently verified filesystem evidence. Official [CLI documentation](https://context7.com/docs/clients/cli) and [SKILL.md](https://github.com/upstash/context7/blob/master/skills/find-docs/SKILL.md) support anonymous lookups. Keep **CLI-only, explicit invocation**, public library questions, no proprietary prompts/code and no billing. If the provider demands login or payment, STOP; no automatic upgrade/fallback.
